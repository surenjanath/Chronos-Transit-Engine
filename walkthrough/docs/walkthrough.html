What the system is

Chronos Transit Engine

Chronos Transit Engine finds planets in starlight. It takes a star's brightness over time from NASA's TESS, Kepler or K2 missions, searches it for the small, regular dips a planet makes when it crosses its star, measures the planet, and decides whether the dip is a planet, an eclipsing binary star, or noise. It is one Django project: server-rendered pages, the science pipeline, and the archive. This guide walks through every page in the order you would use them.

  • Ingest. Any TESS, Kepler or K2 target from MAST by name, a CSV upload, or a simulated star.
  • Clean. Median normalisation, a rolling sigma clip, and a Savitzky-Golay detrend with the transit masked.
  • Search. Box Least Squares over 0.5 to 30 days on all CPU cores, with period-alias correction.
  • Measure. Period, depth, duration, planet radius (with a limb-darkened fit and 1σ errors), orbit size and temperature.
  • Vet. Odd/even depth, a secondary eclipse at any orbital phase, centroid motion, V-shape, radius and duration.
  • Classify. A five-network ensemble of dual-branch 1D-CNNs, plus a second stage that weighs the vetting evidence.
  • Look further. Each signal and the star's own variability are removed, then the remainder is searched again for more planets.
  • Check itself. A blind benchmark on held-out real stars, injection and recovery, golden targets and written acceptance criteria.
  • Locate. A zoomable map of about 4,800 real planetary systems, with distances and travel times from Earth.
  • Record. A hash-chained JSONL audit log per run, Parquet archives, and SQLite or PostgreSQL storage.
  • Run it. ./run.sh starts the engine on http://127.0.0.1:8765. The first start builds a virtualenv, applies migrations and trains the classifier if no checkpoint exists.

Start with a star

Every run starts on this page. Choose where the photometry comes from, describe the host star if you want to override the catalogue, and start the full pipeline.

  • MAST archive. Enter a TIC or KIC id or a name such as WASP-12, pick the mission, and optionally Search MAST to choose a specific sector or quarter. Separate several targets with commas to queue a batch.
  • Synthetic injection. Simulate a star with a planet or binary of your choosing, useful for testing the pipeline.
  • CSV upload. Run the pipeline on your own light curve.
  • Host star. Effective temperature, radius and mass. Left on auto, MAST targets use the TESS Input Catalog; otherwise a solar-type star is assumed.
  • Pipeline overrides. Per-run changes to the saved defaults (sigma-clip threshold, detrend window, period range).
  • While it runs. The run page reports progress in plain words, shows the eleven stages and the time elapsed, and keeps a running list of what has been found so far. MAST targets download on first use, then run in 10 to 30 seconds.

The verdict, and the planet it measured

A finished run opens on its verdict. This example is WASP-12 from TESS sector 20: a 94.2% planet probability, a signal-to-noise of 328 from 21 transits, and the disposition Vetting queue, meaning a high-confidence transit that is ready for human review.

  • Actions. Back to all runs, open the target, see the star on the map, re-run, or delete.

Run page · is it really a planet?

False-positive checks and the NASA cross-match

Below the verdict, the engine lists every false-positive check it made and compares its result with NASA's catalogue. Human vetting and the archived data products sit alongside.

  • False-positive diagnostics. Odd/even depth, secondary eclipse at phase 0.5, in-transit centroid shift, transit shape, fitted against theoretical duration, out-of-transit scatter, shape-derived geometry and stellar density.
  • A real occultation is not held against a planet. A second dip counts against a planet only when it is too bright for a planet to produce, so a hot Jupiter like WASP-12 b raises no flag.
  • NASA Exoplanet Archive cross-match. The run is matched against confirmed planets, TOIs and KOIs. Here it matches WASP-12 b at the same period, with the radius within about 5% of the catalogued value.
  • Human vetting. Add an optional reviewer note (written to the audit trail), then Confirm candidate or Mark false positive.
  • Archive. Download the light curve, periodogram, folded curve and CNN tensors as Parquet, and the audit log as JSONL.

Run page · the classifier

The classifier at work

The classifier diagram is drawn with this run's own folded light curve as input and its own probabilities as output. While a run is in progress the same diagram sits idle until its stage arrives, then animates.

  • Two branches. A global branch sees the whole orbit in 201 bins; a local branch sees the transit in 61 bins, in four views: all transits, odd, even, and the window half an orbit later.
  • Ensemble. Five networks are trained, each holding out a different fifth of the real training stars.
  • Second stage. A small ensemble combines the CNN probabilities with the vetting evidence. For WASP-12 b the CNN alone gave 58.6% planet; the vetting evidence moved the final answer to 94.2%. The final answer is what every run reports.
  • Every transit, stacked. One row per observed transit, so a single odd event stands out.
  • What the classifier looked at. Occlusion saliency for the local and global views: which parts of the curve moved the answer.

Run page · the data

Light curve, periodogram and folded transit

The plots section shows the photometry the run was built from and the search that found the period. All plots can be dragged to zoom.

  • Light curve. 16,551 cadences over 26.3 days at 2-minute cadence. Switch between Normalized + trend and Detrended. Dashed lines mark predicted transit times from the fitted ephemeris.
  • BLS periodogram. Signal residue over 15,192 trial periods, with the best period labelled at the peak.
  • Phase-folded transit. Every transit folded onto one curve, shown as the exact tensors the CNN receives: Local (61 bins) or Global (201 bins).
  • Period aliases. The best peak and its simple multiples are re-examined on a fine grid, and the period is doubled or tripled when only every second or third epoch shows a transit.

An audit trail for every stage

Benchmark · real stars with known answers

Scored on real stars it never saw

The benchmark page scores the classifier on real Kepler stars labelled by the Kepler Science Office: planet candidates, astrophysical false positives and non-transiting phenomena. A fifth of the stars are held out and never used for training.

  • The data. 990 real stars, 330 per class; 802 used for training, 188 held out. A star's split is fixed by its KIC number.
  • CNN ensemble alone. Planet-versus-rest AUC 0.982, PR-AUC 0.966, 90.4% three-class accuracy.
  • With the second stage (what every run reports): AUC 0.985, PR-AUC 0.973, 91.0% accurate.
  • Targets. AUC at least 0.96 and PR-AUC at least 0.88.
  • ROC curves and a confusion matrix show where the mistakes fall.

Benchmark · injection and recovery

Injection and recovery

Injection and recovery measures completeness: limb-darkened transits of known period and depth are injected into quiet real Kepler stars and run blind through the whole pipeline.

  • From S/N 10: 98% recovered.
  • At the 7.1 detection threshold: 50%.
  • Below S/N 4.5: 4%, which should be near zero and is the false-alarm floor.
  • The table lists, for each injected S/N, how many periods were found, detected and called planet.
  • On variable stars the further-signal search recovered 46 of 48 planets injected behind the star's own signal.

Blind, end to end

Automation · champion and challenger

New data in, better model out

Automation runs cycles on a schedule so the engine keeps pulling new data and learning from it. It is off by default and can be started by hand with Run a cycle now.

  • New targets. The newest TESS Objects of Interest not yet in the catalogue are fetched from MAST and run through the full pipeline.
  • New labels. More Kepler stars with settled archive dispositions are downloaded into the training and held-out sets.
  • Retraining. Once enough new stars arrive the classifier is retrained. The new model replaces the active one only if it scores no worse on the fixed held-out real stars.
  • Schedule. Minutes between cycles, new TOIs per cycle, new labelled stars per cycle, and how many new stars trigger a retrain.
  • Model versions. Every training run, accepted or not, with its AUC on real and simulated data.
  • For unattended use without the web server: python manage.py autopilot --loop.

In summary

From starlight to a vetted candidate

Chronos Transit Engine takes raw starlight to a measured planet, a decision you can audit, and a place on the map. It is candid about what it cannot yet do.

  • No confirmed new planet. Across the real stars analysed, every signal sent to the vetting queue is a NASA-confirmed planet except KOI-143.01. Confirming a planet takes independent follow-up.
  • Variable stars. Two of 48 injected planets are still missed, and 2 of 45 variable stars get a spurious extra signal. Additional signals are candidates for inspection.
  • Speed. A four-year Kepler star takes 40 to 190 seconds end to end; a 27-day TESS sector takes a few seconds.
  • The map. Orbits are drawn face-on, and 28 planets with no measured distance are left off.
  • Useful commands. manage.py seed, build_kepler_dataset, train_model, benchmark, injection_study, autopilot, verify.
